# 연속 구매 효과 겹쳐 재생

## 요청·승인 상태

2026-10-23 사용자 보정: 기존 전체 투입/배출 완료를 기다리는 순차 연출을 폐기한다. 추가 클릭 즉시 두 번째 동전 투입 효과가 시작되고, 두 번째 음료도 첫 음료 뒤를 따라 나오며 동시에 움직여야 한다. 현재 읽기·계획 완료, 사용자의 “진행시켜”로 PAVE 코드/테스트 통합 작성 승인 완료.

## 적용안

- 성공 구매마다 별도 연출 인스턴스를 즉시 시작한다. 첫 동전/음료가 끝나기를 기다리지 않는다. 각 클릭 간격에 맞춰 동전과 음료가 연달아 이동하고 여러 구매 효과가 동시에 존재한다.
- 현재 동전 투입·누운 음료 배출·능력 버튼 도착 경로와 속도/아트는 재사용한다. 동일 스크립트를 구매마다 인스턴스화하며 기존 연출을 재시작하거나 끊지 않는다. 테스트는 0.1초 간격 두 입력에서 첫 연출 완료 전 두 동전/두 배출 아트가 공존함을 검증한다. 고정 최소 구매 간격이나 새 연타 제한은 도입하지 않는다.
- 결제/즉시 지급/저장/2% 가격/부족 무차감·수색·능력 입력 허용 유지. 각 구매 완료를 고유한 구매 결과에 연결해 같은 음료 반복/완료 순서 차이에도 다른 결과가 소비되지 않도록 한다. 피버는 해당 결과의 배출 완료 시 발동한다.
- 기존 상단 능력 알림은 각 결과가 읽힐 수 있도록 기존 컴포넌트에서 순서대로 표시하되 동전·배출 연출을 기다리게 하지 않는다. 새 패널/레이아웃/스타일은 만들지 않는다.
- 각 연출의 투입구/배출구/능력 버튼 목표가 resize에 함께 맞춰지고 모달 뒤에 표시되며 ESC pause/resume을 따른다. 완료/씬 종료 시 임시 FX·tween을 정리한다. 대기 연출/일시 피버는 저장하지 않으며 이미 지급한 보상을 재지급하지 않는다.

## 소유자·작성 전 검사

- owner-found: src/features/play/play.gd _play_purchase_queue가 현재 단일 tween/FX 완주를 기다리는 원인이다. 구매별 동시 연출 관리로 전환하되 기존 Play의 입력/연출 책임 안에서 처리한다. 새 범용 연출 프레임워크는 만들지 않는다.
- owner-found: src/features/play/effects/coin_insert_fx.gd와 drink_dispense_fx.gd의 begin/advance/좌표·수명 경계를 재사용한다. 스크립트 복제 없이 여러 인스턴스 생성. 기존 미리보기/참조용 단일 FX와 실제 구매 FX의 소유를 구분하고 불필요해진 단일 전용 필드는 직접 호출자·테스트와 함께 정리한다.
- owner-found: src/game/progress_state.gd pending_purchases와 game_session.purchase/finish_purchase에서 실제 결과 완료를 개별 구매와 대응시킨다. UI에 결제/획득 원장을 중복 생성하지 않고 저장 형식은 유지한다.
- owner-found: ability_toast.gd는 알림 수명/표시 소유자다. 개별 배출 완료가 기존 알림을 끊어 버리지 않도록 기존 컴포넌트 내부에 표시 순서만 관리한다.
- 직접 호출·회귀: _position_coin_slot, _show_acquired_ability, purchase_price/drink_dispense/gameplay/purchase_area/menu/search_fever/punch_fever/expanded_skills. FIFO 완주 대기를 기대하는 회귀를 겹침/개별 결과 완료로 갱신한다.
- UI: 기존 A 공유 테마/PixelButton·음료 아트·투입 FX·상단 알림 재사용. 편집 가능한 Penpot 구매 애니메이션 상태에 겹친 동전/음료 시차 상태를 반영하고 Notion의 순차 재생 규칙을 수정한다.
- 기본 계획은 신규 런타임/테스트 파일 없음. 기존 owner 파일을 수정한다. 이 계획 파일만 승인·검증 경계 기록으로 추가한다.

## 추가 사용자 보정과 검증 결과

- 사용자 추가 요청: 기본 물·녹차가 Play 자판기에서 보이지 않는 문제. 새 게임의 마스크는 3으로 정상이나 최대 강화 시 purchasable_drinks에서 빠져 진열에서도 사라지는 원인을 확인했다. 기존 `_refresh_vending_display`와 vending_display_test 두 파일의 20줄 이내 보정으로 해금 진열을 유지한다. 최대 강화의 추첨 제외 규칙은 유지한다.
- 16개 기존 feature/integration 회귀 모두 통과. Godot 4.7.2 공식 실행 파일로 GPU drink_dispense/vending_display 검증도 통과. 두 동전의 opacity와 시차 좌표, 첫 완료 전 두 음료 공존, 결과 ID·중복 완료·저장·알림·pause/resize 검증. 최대 강화 물·녹차가 화면에 남는 것도 캡처로 확인했다.
- 공식 editor parse/resource 검사와 git diff --check 통과. 초기 sandbox editor 실행의 AppData 쓰기 제한은 승인된 동일 공식 실행 파일로 재검증해 해소했다. formatter/linter/export 설정은 이번 범위 밖의 기존 setup gap이다.
- Notion의 현재 피버/입력 문단과 화면·보상 표현 문단을 갱신 후 reload 검증. 기존 과거 날짜 섹션은 현재 원문에 없어 해당 현행 문단만 수정했다. Penpot 지정 파일의 구매03/05에 기존 FX 인스턴스를 복제하고 시차 좌표를 배치, 겹친 동전/음료 상태로 이름을 바꾼 뒤 reload 확인했다.
- Knowledge Delta: 코드 안내의 FIFO 계약을 구매 ID별 병렬 FX·결과 완료/순차 토스트로 정정하고 해금 진열 회귀를 기록. 일반 연출 변경으로 별도 troubleshooting 문서나 신규 런타임 파일은 필요하지 않다.
- 실제 diff: 기존 효과 스크립트·토스트·표시 테마 재사용, UI는 연출 수명만 관리하고 결제/보상/피버 판정은 세션에 유지. 쓰지 않는 단일 CoinToken/Symbol 및 FIFO 필드 제거. 테스트 대기 helper는 기존 fixture에 추가하고 테스트 전용 런타임 별칭은 만들지 않았다.
