# 자판기 이미지 분해 · 2026-10-18

> 2026-10-20 페이지 정리: 개별 아트·부품은 현재 02 · 에셋, 공통 UI는 00 시스템에 보관한다. [현재 위치·컴포넌트 검증](../page-organization/README.md)을 따른다. 아래 생성 manifest와 ID는 제작 당시 기록이다.

사용자 지정 원본은 02 · 에셋 라이브러리의 `자판기 · 확정 음료 15종 · 5×3` 보드다. 통합 이미지의 음료를 추출해 기존 `음료수 에셋` 원본 15개의 그림을 교체하고, 자판기 부품 원본과 연결된 조립 복사본을 제공하는 작업이다. 새 페이지나 게임 코드는 만들지 않는다.

## 최신 수정 · 상품 외 본체 통합

사용자가 부품을 너무 많이 분리했다고 지적하고 상품을 제외한 본체를 합치도록 요청했다. 기존 부품 36개를 조립한 빈 본체를 손실 없는 WebP 한 장으로 내보내 `Clicker / Approved / Vending15 / 본체 · 상품 제외 · 통합` 원본 컴포넌트로 등록했다. 기존 부품 원본 36개와 이름표는 편집 시트에서 제거했고, 같은 보드를 `자판기 본체 · 상품 제외`로 정리했다. 해당 보드에는 지정 B 기반의 빈 본체 원본도 별도 한 개 있다. 음료 15종의 개별 원본과 ID는 유지했다.

현재 본체 원본 ID는 `penpot-manifest.json`의 `currentConsolidation`에 기록한다. 아래 51개 조립 구조와 36개 부품 목록은 이전 검수 이력이다. 이번 확인 시 과거 조립 원본·복사본은 레이어 검색에 없었으므로 임의로 재생성하지 않았다. 원래 통합 이미지 보존 보드는 남아 있다.

## 이전 분해 작업 이력

- 로컬 산출물: 음료 15종, 자판기 부품 36종의 투명 PNG와 SVG 조립 소스 완료.
- 음료의 불투명 픽셀 179,404개를 원본 좌표와 대조해 RGB 불일치 0개를 확인했다.
- `음료 이미지 교체·자판기 분해 전`이라는 Penpot 버전을 저장했다.
- 사용자 지시에 따라 MCP 대신 Computer Use로 기존 02 페이지에 적용했다. 기존 음료 원본 15개의 컴포넌트·이미지 레이어 ID를 유지하며 그림을 교체했다.
- `자판기 부품 원본 · 36종` 보드에 개별 원본 컴포넌트 36개를 등록했다.
- 기존 `자판기 · 확정 음료 15종 · 5×3` 보드를 부품 36개와 음료 15개의 연결된 복사본으로 재조립하고, 전체를 메인 컴포넌트로 등록했다. 조립 보드의 직접 자식 51개 ID를 화면의 레이어 목록과 대조했다.
- 전체 연결 복사본 `자판기 · 조립 복사본 · 원본 연결`을 추가했고, 오른쪽 컴포넌트 패널의 원본 연결과 1024×1536 크기를 확인했다. 통합 비트맵은 `자판기 · 통합 이미지 원본 보존` 보드에 보존했다.
- 저장된 파일을 새 편집 탭에서 다시 열어 부품 시트·전체 복사본·조립 원본의 메인 컴포넌트 상태와 최종 외형을 확인했다 (`saved-assembly-penpot.png`).

## 산출물

- `drinks/`: 원본 이미지에서 추출한 15종. 기존 v9의 이름과 컴포넌트 ID를 유지한다.
- `parts/`: 본체, 간판, 진열창 프레임, 조명·배경·선반 각 3종, 상품 버튼 15종, 결제부 4종, 배출구·통풍구·다리·하부 프레임을 포함한 36종.
- `assembly.svg`, `empty-assembly.svg`: 개별 부품을 조립한 SVG 소스. 원본 비트맵을 벡터 클리핑 경로로 나눈 구조이며 전체를 벡터로 다시 그린 것은 아니다.
- `drinks-preview.png`, `assembly-preview.png`, `empty-assembly-preview.png`: 로컬 검수 이미지.
- `geometry.json`: 원본 좌표의 분리 경계와 기존 음료 컴포넌트 ID.
- `local-verification.json`: 파일·원본 픽셀 검수 결과.
- `penpot-manifest.json`: 실제 UI에서 생성·확인한 원본/복사본 레이어 ID와 검증 결과.
- `drinks-penpot.png`, `parts-penpot.png`, `assembly-main-penpot.png`, `assembly-copy-penpot.png`: 실제 Penpot 편집 화면 검수 캡처.
- `parts-sheet-ui.svg`: 이름표와 부품을 배치한 가져오기 소스. 전송 크기를 줄이기 위해 나눠 붙여넣고 UI에서 개별 컴포넌트로 등록했다.

통합 원본에는 음료 뒤에 가려진 배경 픽셀이 없다. 음료 제거 시 잔상이 남지 않게 진열 배경 3개는 원본에서 채취한 크림색 면으로 복원했다. 음료와 자판기 외장의 그림을 새로 생성하지 않았다.

## 생성과 적용

로컬 PNG·SVG는 `trace_geometry.py` → `build_plan.py` → `render_assets.js`로 생성한다. 실제 반영은 Chrome의 Penpot 편집 UI에서 가상 클립보드 붙여넣기, 속성 붙여넣기, 컴포넌트 생성, 원본 복사로 진행했다. MCP로 준비했던 미실행 적용 배치는 제거했다. 인증 키는 산출물·소스·영구 설정에 저장하지 않는다.

음료 원본은 192×288이며 그림을 1.5배로 표시하고 하단 기준선을 272에 맞췄다. 자판기 안의 연결 복사본은 128×192로 축소해 원본 이미지 좌표에 배치했다. 부품은 원본 픽셀 크기를 유지했다.

## 원본과 복사본 기능 확인

Penpot은 Main component와 연결된 Component copy(instance)를 지원한다. 원본 변경은 복사본에 반영되며, 복사본의 개별 속성은 override할 수 있다. Assets에서 끌어오거나 원본을 복제하면 연결된 복사본이 된다. 연결 해제는 Detach instance다.
